# Development demo dataset

Run explicitly with `php artisan db:seed --class=DevelopmentDemoSeeder`. It is not included in DatabaseSeeder and refuses environments other than local/testing. Set `DEV_DEMO_PASSWORD` in the untracked `.env` first (minimum 12 characters); no credential is hard-coded in the seeder or production logic.

- 50 clearly marked `[DEMO]` Sales: 36 active, 8 pending, 3 rejected, 3 blocked. Emails `demo.sales.01@example.test` through `demo.sales.50@example.test`. All share the local demo password. Existing admin credentials are retained; if no active admin exists, the factory creates `demo.admin@example.test` with the same development password.
- Uses up to 12 existing active Dealers, preferring the official Toyota directory. If there are fewer, additional clearly marked Dealer factory fixtures fill the gap. Existing Dealers and Sales are never deleted or reassigned.
- 500 submissions: 300 approved, 150 pending, 50 rejected. Only active or formerly active/now blocked demo Sales have submissions; blocked Sales submissions precede their block timestamp. Dates cover the current week/month and four previous months, relative to the application timezone. Different record counts produce distinct rankings. One approved record demonstrates submission before a month boundary/review after it; two pending records deliberately duplicate already-approved Facebook identities.
- Customer names, phone numbers, Facebook URLs, vehicle details and moderation notes are synthetic. Names/notes are marked `[DEMO]`, phones use `000…`, license plates use `DEMO-…`; these are not real Facebook members or evidence of actual Toyota ownership.
- Each submission has its own private PNG placeholder clearly labeled synthetic evidence. Files use the existing authenticated evidence endpoint and remain outside public storage. Database failure rolls back inserted records and removes newly generated files.
- Seeds account/submission review history and attempts two completed monthly + two completed weekly awards, with three Sales and three Dealer snapshot winners each. Periods already occupied are skipped; periods lacking three Sales/Dealers are skipped. Winners come from the existing leaderboard/AwardResults services and are inserted while the award is draft, then published as demo fixtures. No production publication endpoint or business rule is added. Existing awards are untouched.
- A complete set of reserved demo accounts makes subsequent runs a no-op, preserving manual moderation, edited records, timestamps and published snapshots. Partial/conflicting reserved accounts abort seeding instead of overwriting user data. This is a one-time dataset, not a synchronizer or destructive reset.

For active Sales use `demo.sales.01@example.test` (through `.36`); pending `.37`–`.44`, rejected `.45`–`.47`, blocked `.48`–`.50` exercise status screens. Password is `DEV_DEMO_PASSWORD`, not the UserFactory test default. Do not import this dataset into production.

Validation on 2026-10-04: seeded development successfully; repeated seed preserved existing data. Full suite passed 443 tests / 2,762 assertions. Real browser checks passed 51 page loads at 320/390/1440px, including admin/Sales login, dashboards, first/later ranking/moderation pages, duplicate detail, awards and authenticated private PNG evidence; no page overflow or JavaScript errors. No UI changes or new migrations were needed.
